MarkVSpec 文書構造

MarkVSpec 文書内の prose と構造化 DSL の位置を議論するときに使う canonical 用語です。ticket、parser、preview、documentation で同じ名前を使います。

Annotated Skeleton

Document Header Front Matter と H1

--- metadata と # SCR-* Title

文書 ID、title、route など、文書全体の metadata を置きます。

Document Lead 最初の Section より前の目的説明

H1 の後、最初の ## より前の Markdown 本文。

screen、template、partial、example 全体の目的を書きます。

Section level-2 の認識済み section

## States、## Layout、## Elements、## Actions

認識済み section は parser が解釈し、未知の section は Markdown として保持します。

Section Lead 構造化定義より前の prose

section heading 直下の Markdown 本文。

その section の表、一覧、entity summary より前に表示します。

Entity Block level-3 の定義単位

### A1:A-Submit Submit、### E-EmailInput Input

Action、Element、Validation、Business Rule など、ID を持つ対象の定義です。

Entity Lead entity DSL より前の prose

entity heading 直下の Markdown 本文。

その entity の目的や設計意図を書きます。

Structured Body 機械可読な DSL

- Triggered、- Process P1: ...、- label: ...

parser、validator、preview が MarkVSpec semantics として解釈します。

Entity Notes entity DSL の後の prose

structured list の後、同じ entity 内に残る Markdown 本文。

補足、実装メモ、設計上の注意を書きます。

Section Notes section 構造化定義の後の prose

entity blocks や structured definitions の後の Markdown 本文。

section 全体に対する後置補足です。

Free-form Section Markdown-only section

## Notes、## Open Questions、未認識の ##

構造化 DSL としては解釈せず、author が書いた Markdown として保持します。

Canonical Terms

Document HeaderYAML Front Matter と最初の level-1 heading。
Document LeadH1 の下、最初の level-2 section より前の Markdown。
Section## States や ## Actions のような level-2 heading。
Section Leadsection 冒頭、構造化 entry より前の Markdown。
Entity BlockID を持つ level-3 definition unit。
Entity Leadentity heading 直下、structured body より前の Markdown。
Structured BodyMarkVSpec semantics として解釈する list / table。
Entity Notesentity structured body の後の補足 Markdown。
Section Notessection の structured definitions 後の補足 Markdown。
Free-form SectionDSL として解釈しない Markdown section。

Source Range Example

---
      id: SCR-LOGIN
      type: screen
      title: Login
      ---
      # SCR-LOGIN Login

      画面全体の説明。

      ## Elements

      element catalog 全体の説明。

      ### E-EmailInput Input

      email 入力の目的。

      - label: Email
      - type: email

      input 固有の実装メモ。

      ### Section Notes

      Elements 全体への補足。

      ## Notes

      設計中の open note。
  1. Document Header: Front Matter と # SCR-LOGIN Login。
  2. Document Lead: 「画面全体の説明。」
  3. Section: ## Elements。
  4. Section Lead: 「element catalog 全体の説明。」
  5. Entity Block: ### E-EmailInput Input。
  6. Entity Lead: 「email 入力の目的。」
  7. Structured Body: - label と - type。
  8. Entity Notes: 「input 固有の実装メモ。」
  9. Section Notes: ### Section Notes の内容。
  10. Free-form Section: ## Notes。

Placement Rules

Lead は対象の前に表示します。 Section Lead は section の table / list / summary の前に、Entity Lead は entity detail の冒頭に表示します。
Notes は対象の後に表示します。 Entity Notes は entity の structured content の後、Section Notes は section の structured definitions の後に表示します。
Structured Body は semantic data です。 parser、validator、preview、export はこの内容に依存します。prose 領域は Markdown として保持しますが DSL semantics ではありません。
HTML comment は authoring comment です。 prose 領域にある <!-- todo --> のような comment は preview / export に表示しません。

推奨する呼び方

「構造化ブロックの上」「list の下」のような曖昧な表現ではなく、Section Lead、Entity Lead、Entity Notes、Section Notes を使います。
