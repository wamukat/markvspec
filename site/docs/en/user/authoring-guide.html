MarkVSpec HTML Authoring Guide

This guide shows how Markdown source turns into preview and generated design-document output. The examples use small source snippets and hand-written static HTML mocks. They follow the current preview visual language, but they do not execute the production preview engine and are not renderer-perfect output.

target: L-*

  • The target is a layout or element slot that already exists in the wireframe.
  • The rendered element is declared once under ## Elements, then referenced by ID.
  • Use this when the result is structured UI, such as a banner, badge, or panel.

Markers and References

ID chips connect prose, markers, and source IDs

#{ID} 
## Notes

Review the required email behavior in #{E-EmailInput}
before changing #{A-SubmitLogin}.

### E-EmailInput Input
- label: Email

Review the required email behavior in E-EmailInput before changing A-SubmitLogin.

E1 E-EmailInput
Email
  • Use #{ID} in prose to point to a screen, layout, element, action, rule, or validation ID.
  • The preview can show a compact reference chip in prose and a marker near the visual element.
  • Markers are review aids. They should not force authors to add low-level layout instructions.
