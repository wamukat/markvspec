MarkVSpec Document Structure

Use these canonical names when discussing where Markdown prose and structured DSL data belong in a MarkVSpec document. The same terms are used in tickets, parser behavior, preview behavior, and documentation.

This is a compatibility page for the legacy docs/user path. Use the new Start, Guide, Reference, and Recipes entry points for current documentation.

Annotated Skeleton

Document Header Front Matter and H1

--- metadata, then # SCR-* Title

Document-wide identity, title, route, and metadata.

Document Lead Purpose before the first section

Markdown body after H1 and before the first ##.

Use this for the screen, template, partial, or example purpose.

Section Level-2 recognized section

## States, ## Layout, ## Elements, ## Actions

Recognized sections are interpreted by the parser; unknown sections are preserved as Markdown.

Section Lead Prose before structured entries

Markdown body immediately below the section heading.

Displayed before that section's table, list, or entity summary.

Entity Block Level-3 definition unit

### A1:A-Submit Submit, ### E-EmailInput Input

An ID-bearing definition such as an Action, Element, Validation, or Business Rule.

Entity Lead Prose before entity DSL

Markdown directly below the entity heading.

Use this for the entity's purpose or design intent.

Structured Body Machine-readable DSL

- Triggered, - Process P1: ..., - label: ...

The parser, validator, and preview interpret this region as MarkVSpec semantics.

Entity Notes Prose after entity DSL

Markdown after the structured list, still inside the entity.

Use this for caveats, implementation notes, or background.

Section Notes Prose after section structures

Markdown after entity blocks or structured definitions.

Use this for notes that apply to the whole section.

Free-form Section Markdown-only section

## Notes, ## Open Questions, or an unrecognized ##

Preserved as authored Markdown, not interpreted as structured DSL.

Canonical Terms

Document HeaderYAML Front Matter and the first level-1 heading.
Document LeadMarkdown below the H1 and before the first level-2 section.
SectionA level-2 heading such as ## States or ## Actions.
Section LeadMarkdown at the beginning of a section, before structured entries.
Entity BlockAn ID-bearing level-3 definition unit.
Entity LeadMarkdown directly below an entity heading and before its structured body.
Structured BodyLists and supported tables interpreted as MarkVSpec semantics.
Entity NotesSupplemental Markdown after an entity structured body.
Section NotesSupplemental Markdown after a section's structured definitions.
Free-form SectionA Markdown section preserved without DSL interpretation.

# SCR-LOGIN Login

Explains the whole screen.

## Elements

Element catalog notes.

### E-EmailInput Input

Collects the user's email.

- label: Email
- type: email

Input-specific implementation note.

### Section Notes

Notes for all elements.

## Notes

Open authoring notes.
  1. Document Header: Front Matter plus # SCR-LOGIN Login.
  2. Document Lead: Explains the whole screen.
  3. Section: ## Elements.
  4. Section Lead: Element catalog notes.
  5. Entity Block: ### E-EmailInput Input.
  6. Entity Lead: Collects the user's email.
  7. Structured Body: - label and - type.
  8. Entity Notes: Input-specific implementation note.
  9. Section Notes: ### Section Notes content.
  10. Free-form Section: ## Notes.

Placement Rules

Lead appears before the target. A Section Lead appears before the section's generated table, list, or summary. An Entity Lead appears at the start of that entity's detail.
Notes appear after the target. Entity Notes follow the entity's structured content. Section Notes follow the section's structured definitions.
Structured Body is semantic data. Parser, validator, preview, and export behavior may depend on it. Prose regions are preserved as Markdown but do not define DSL semantics.
HTML comments are authoring comments. Comments such as <!-- todo --> in prose regions are not displayed in preview or export output.

Recommended Language

Use Section Lead, Entity Lead, Entity Notes, and Section Notes instead of vague phrases such as "above the structured block" or "below the list".
